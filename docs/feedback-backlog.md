# 反馈清单(按类型归档)

来源:2026-09 使用反馈。分四类:**A 真 bug** / **B 设计冲突(需拍板)** / **C 功能缺失** / **D 已有设计但没说明**。
每项标注:现状 → 我的判断 → 建议做法。

## A. 真 bug(明确做错了)

| # | 问题 | 现状 | 建议 |
|---|---|---|---|
| A1 | **复习两个按钮结果相同** | 复习时选"认识/不认识"都只把词标成 `learning` 并显示释义 | 两个按钮必须产生不同结果:认识 → 提升 SRS 等级/可能转 `mastered`;不认识 → 重置等级并回到当天队列 |
| A2 | **复习完成后状态是"学习中"** | 一轮复习结束,生词本里显示"学习中",没有"已复习" | SRS 里区分"待复习/复习中/已巩固",并让生词本显示出来 |
| A3 | **阅读进度到不了 100%** | 需滑到底并**停留 5 秒**才判定读完;点"阅读完毕"按钮只到 95% | 三个入口要一致:停留计时、按钮、划到底。按钮点了就该 100%(或明确写清"需停留 N 秒") |
| A4 | **"已在生词本"按钮语义错误** | 点一下实际是"移出生词本",且与另一个按钮重复(没删干净) | 只保留一个按钮,文案直接写"移出生词本" |
| A5 | **今日新学与本机时间强绑** | 改本地时间可反复标记"今日新词";且昨日标记无痕迹 | 见 B3(合并进生词本) + A6 |
| A6 | **连续打卡跟本地时间走** | 改本地时间即可刷天数 | 与网络时间比对(见下"服务器时间"一节) |
| A7 | **备份把文章正文也塞进去了** | 导出备份 56 KB,剪贴板放不下、贴不完整 | 备份只存用户数据(生词/进度/设置),文章按 id 引用,不存正文 |
| A8 | **导出生词本 CSV 混入释义** | 每行带中英释义,人看不了 | CSV 只留:单词、词性、中文、来源、状态(需要的话另出一个"含释义"选项) |

## B. 设计冲突(需要你拍板)

| # | 冲突 | 说明 | 我的建议 |
|---|---|---|---|
| B1 | **没验邮箱 ↔ 忘记密码** | 假邮箱也能注册,于是"忘记密码"对那些号形同虚设 —— 功能自相矛盾 | 注册时做**真实邮箱校验**(格式 + 域名 MX 记录查询);否则忘记密码就是摆设 |
| B2 | **本地数据 ↔ 多个云端账号** | 本地数据能被反复上传到不同账号 → 两个号内容一样;退出登录后本地还在 | 登录时**二选一**:用云端覆盖本地 / 用本地上传云端 / 新建独立空间;并给本地数据一个 id,只有同一 id 才允许覆盖(见 C5) |
| B3 | **今日新学 ↔ 生词本** | 两套独立逻辑,今日新学只是给首页计数器 +1,第二天清零、看不到学了什么 | **合并**:读文章时加入生词本的词自动算"今日新学";首页计数器点进去 = 今日新增列表(可做成日历) |
| B4 | **首页生词本计数含已掌握** | 首页显示 20,点进去发现 20 个都已掌握 | 首页只算"未掌握";已掌握的在生词本页单独分区/排序到底部 |
| B5 | **备份导入可被无限复制** | 同一份 JSON 发给多人导入,云端可造出大量同内容账号 | 备份里带**来源 id**;导入时校验 id;覆盖成功后重置 id(你提的方案,赞同) |

## 服务器时间校验(A6 的落地方式)

```
客户端请求任意 HTTPS 响应 → 读响应头 Date(或用一个返回时间的公开接口)
与本地时间差 > 容忍值(如 5 分钟)→ 视为"改过时间"
→ 打卡与今日新学改用服务器时间判定;并给出提示而非直接判无效
```
注意:自用 App 不该因为这个"封号",提示 + 不计数即可。
