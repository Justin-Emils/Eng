# v1.1.0 · 在线账号与云同步

这一版把 App 从「纯本地工具」补成了「有账号的正常 App」:可以用邮箱注册登录,学习数据能上传到云端,换手机时登录即可取回。

## 新增

- **在线账号体系**
  - 邮箱注册:**注册即登录,不需要收确认邮件**(后端已关闭邮件确认)
  - 邮箱登录:登录态本地持久化,access token 到期自动续期
  - 忘记密码:邮箱收到验证码 → 输入验证码 + 新密码 → 自动登回来(不用点邮件链接)
  - 修改密码:已登录状态直接改,不需要任何邮件
  - 退出登录:只停止同步,本机的生词与进度全部保留
- **云同步**
  - 「上传本机数据到云端」/「从云端恢复」:整份备份(生词本、复习进度、阅读记录、每日目标、设置、昵称头像)走网络同步
  - 账号页显示**云端备份的真实状态**:从服务器回读的备份词数与更新时间,不是本地推测
  - 换手机流程:新机登录 → 点「恢复」→ 数据回来
- **自定义头像**:从相册选图(拷贝进 App 目录,不会被系统清理),或从 12 个 emoji 里选
- **备份与恢复**:整份学习数据导出到剪贴板 / 从剪贴板导入(云同步之外的第二条退路)

## 修复

- **未登录时不再显示成「已有账号」**：「我的」顶部原来无论登不登录都显示头像、昵称框和「账号 ›」,现在明确区分「本机档案(未登录)」与「已登录 xxx@邮箱」,入口也按状态显示「登录 ›」/「账号 ›」
- **版本号回归真实**：`app.json` 的 version 从项目第一天起就是 `1.0.0`,发版只打 tag 没同步它,导致「关于」里显示的版本一直是假的。本次修正为 `1.1.0`,并把「发版必须同步改 version / versionCode / 重新 prebuild」写进 README
- **验证码位数不再写死**：原来按 6 位校验,而 Supabase 实际发的是 8 位,导致验证码根本提交不了。现在只判「纯数字 + 6~10 位」,位数由后端决定
- **邮件通道出错时给出可定位的提示**：SMTP 没配好时后端返回 500,原来会被兜底成「服务器暂时不可用」;现在直接指出是邮件通道配置问题

## 安装

- 文件名:`考研英语阅读-v1.1.0.apk`
- 架构:`arm64-v8a`(适用于 2017 年后的绝大多数安卓手机)
- 签名:debug 签名,仅供自用侧载;上架需换正式 keystore
- 覆盖安装即可,**本机数据(生词本、进度、设置)不会丢**;从旧版升级后建议先登录并点一次「上传本机数据到云端」

## 说明

- **离线优先不变**:不登录、不联网时阅读、背单词、复习全部照常使用。账号只负责"换手机不丢数据"
- **同步是整份覆盖,不是逐条合并**:两台手机各自改了很多再同步,后上传的会覆盖前一个。跨设备使用建议固定「一台主用 + 定期上传」
- 云端数据由 Supabase 行级权限保护:即使拿到客户端里的公开密钥,也读不到、写不进别人的数据
